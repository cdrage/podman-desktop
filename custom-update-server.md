# Custom HTTPS Update Server Support

## Issue Description

### Problem

Downstream forks of Podman Desktop cannot easily configure the auto-updater to point to their own update server. The updater is hardcoded to use GitHub Releases as the update provider, meaning forks must either use their own GitHub repo's releases or manually patch the build infrastructure.

### Proposal

Add a `update.url` field to `product.json` that allows downstream forks to point the auto-updater at any HTTPS server hosting their binaries. When the field is empty (default), the existing GitHub Releases behavior is preserved. When set, the updater switches to electron-updater's `generic` provider.

A downstream fork would:

1. Set `product.json`:
   ```json
   "update": {
     "url": "https://updates.example.com/my-product"
   }
   ```
2. Build the app normally (`pnpm compile:current`)
3. Upload to their HTTPS server:
   - `latest-mac.yml` (macOS update metadata, generated by electron-builder)
   - `latest.yml` (Windows update metadata, generated by electron-builder)
   - The binary files (`.dmg`, `.exe`, etc.)
4. The app automatically checks `https://updates.example.com/my-product/latest-mac.yml` (or `latest.yml` on Windows) for updates

No other code changes required in the fork.

## Implementation Summary

### Files Modified

#### 1. `product.json`
Added an `update` section with a `url` field. Empty string preserves existing GitHub behavior.

```json
"update": {
  "url": ""
}
```

#### 2. `.electron-builder.config.cjs`
- The `publish` config now conditionally uses the `generic` provider when `product.update.url` is set, otherwise falls back to the existing `github` provider.
- The AIRGAP build block was updated to respect the same conditional logic.

#### 3. `packages/main/src/plugin/updater.ts`
- Added a `setFeedURL()` call in `init()` that reads `product.update.url` at runtime and configures electron-updater's generic provider. This is a runtime safety belt that complements the build-time `app-update.yml` generated by electron-builder.

#### 4. `packages/main/src/plugin/updater.spec.ts`
Added 3 test cases:
- `setFeedURL` is NOT called when `product.update.url` is empty (default behavior preserved)
- `setFeedURL` IS called with `{ provider: 'generic', url: '...' }` when a URL is configured
- `setFeedURL` is called before `checkForUpdates` (correct initialization order)

### How It Works

The change operates at two levels:

- **Build time**: electron-builder reads `product.json` and generates `app-update.yml` (embedded in the app) with the correct provider. It also generates the `latest-mac.yml` / `latest.yml` metadata files that the downstream server needs to host.
- **Runtime**: `updater.ts` calls `autoUpdater.setFeedURL()` to override the provider, keeping `product.json` as the single source of truth.

### Verification

- All 34 unit tests pass (`pnpm exec vitest run packages/main/src/plugin/updater.spec.ts`)
- TypeScript compiles without errors
- Lint checks pass on all modified files

## Testing with a Local Update Server

You can test the full update flow locally using a Podman (or Docker) container running nginx.

### Important Notes

- **macOS code signing:** On macOS, Squirrel (the native updater) validates that the downloaded update has the same code signing identity as the running app. You cannot mix GitHub-signed release binaries with locally ad-hoc-signed builds. Both the running app and the update binary must share the same signing identity. For local testing, always serve your own build artifacts.
- **macOS with Podman:** Use `~/update-server` (home directory), not `/tmp/update-server`. The Podman VM on macOS mounts the home directory but may not have access to `/tmp` on the host.
- **Version verification:** To verify the update actually installed a new version (not just re-installed the same binary), you need two separate builds with different versions in `package.json`. See below.

### Step 1: Get your local IP

Use your machine's local IP (not `localhost`, since the Electron app resolves DNS differently depending on platform):

```bash
# macOS
ipconfig getifaddr en0

# Linux
hostname -I | awk '{print $1}'
```

### Step 2: Set `product.json` to point to your local server

```json
"update": {
  "url": "http://<YOUR_LOCAL_IP>:8080"
}
```

### Step 3: Build the "update" binary (v99.0.0)

Build the binary that will be served as the update. Electron-builder reads the version from `package.json`, so temporarily change it:

```bash
pnpm install
pnpm build

# Set version to 99.0.0 in package.json
# (on Linux, omit the '' after -i)
sed -i '' 's/"version": ".*"/"version": "99.0.0"/' package.json

pnpm compile:current
```

After the build, `dist/` will contain:
- The app binary and ZIP (e.g., `podman-desktop-99.0.0-arm64.zip` on macOS)
- **`latest-mac.yml`** (macOS update metadata) and/or **`latest.yml`** (Windows update metadata)
- These YAML files already contain `version: 99.0.0` with correct checksums

### Step 4: Copy update artifacts to the server directory

```bash
mkdir -p ~/update-server
cp dist/latest-mac.yml ~/update-server/           # macOS metadata
cp dist/podman-desktop-*-arm64.zip ~/update-server/ # macOS binary (Squirrel uses ZIP, not DMG)
# cp dist/latest.yml ~/update-server/              # Windows metadata
```

> **Note:** On macOS, the auto-updater (Squirrel) downloads the `.zip` file, not the `.dmg`. Make sure to copy the ZIP.

### Step 5: Build the "current" binary (v1.0.0)

Now build the version that you will actually run. This must have a **lower** version than what the server advertises:

```bash
# Set version to 1.0.0 in package.json
sed -i '' 's/"version": ".*"/"version": "1.0.0"/' package.json

pnpm compile:current
```

> **Note:** Remember to restore the original version in `package.json` when done (e.g., `git checkout package.json`).

### Step 6: Start the update server

```bash
podman run --rm -d \
  --name update-server \
  -p 8080:80 \
  -v "$HOME/update-server:/usr/share/nginx/html:ro,Z" \
  docker.io/library/nginx:alpine
```

Verify the server is working:

```bash
curl http://<YOUR_LOCAL_IP>:8080/latest-mac.yml | head -2
# Should show: version: 99.0.0
```

### Step 7: Sign and run the app

On macOS:

```bash
codesign --force --deep --sign - "dist/mac-arm64/Podman Desktop.app"
open "dist/mac-arm64/Podman Desktop.app"
```

The app should:
1. Show `v1.0.0` in the status bar
2. Check `http://<YOUR_LOCAL_IP>:8080/latest-mac.yml` on startup
3. Detect version `99.0.0` is available
4. Show "Update available" in the status bar
5. Show the update dialog (if `preferences.update.reminder` is set to `startup`)
6. After clicking "Update now", download the v99.0.0 ZIP from your server
7. After restart, the app should show `v99.0.0` in the status bar

You can watch the app's console output for update check logs. Open DevTools via `View > Toggle Developer Tools` or the keyboard shortcut.

### Step 8: Clean up

```bash
podman stop update-server
rm -rf ~/update-server
```

Remember to reset `product.json` back to `"url": ""` when done testing.

### Using HTTPS (Production-like Testing)

For HTTPS, you can use a self-signed certificate with nginx. However, electron-updater rejects self-signed certs by default. To work around this for testing, you can either:

- Use a tool like [mkcert](https://github.com/FiloSottile/mkcert) to generate locally-trusted certificates
- Use a real domain with Let's Encrypt via a reverse proxy
- Use [ngrok](https://ngrok.com/) or similar to tunnel with a valid HTTPS certificate:
  ```bash
  ngrok http 8080
  # Use the ngrok HTTPS URL in product.json
  ```
